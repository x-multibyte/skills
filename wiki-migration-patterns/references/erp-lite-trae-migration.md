## Decisions Made

1. **Sub-wiki under `~/wiki/`** (not in project dir) — user wanted wiki independent of
   project directory, not tracked in git, surviving project deletion.
2. **Each entity page includes schema table** — useful for quick reference without
   opening the raw source.
3. **Provenance markers not used** since each page has single or pair of sources
   (frontmatter `sources:` is sufficient per skill convention).
4. **Pure-reference files** (roadmap, running-the-app, glossary) left in raw/ with no
   wiki page — they're searchable when needed.

## Post-Migration Additions

After the initial migration, these tools were added:

- **`build-wiki.py`** -> `index.html` — static HTML viewer with dark theme, wikilinks,
  search. Rebuild: `uv run --with markdown python3 build-wiki.py`
- **`sync-wiki.py`** — detects git changes and maps them to wiki pages.
  Commands: `--status`, `--rebuild`, `--reset`
- **Valet domain** — `http://erp-lite.wiki.test/` serves the HTML viewer
  (`valet link erp-lite.wiki`, no restart needed)
- **MCP servers** — `codebase-memory-mcp`, `laravel-boost`, `blatui` added to
  Hermes config for deeper code analysis during sync
