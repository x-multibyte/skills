# LightRAG deployment paths — analysis

Surveyed docs (repo root): AppleContainerSetup.md, DockerDeployment.md, InteractiveSetup.md (mentioned), docker-compose.yml, docker-compose.podman.yml, docker-compose-full.yml, scripts/setup/apple-container.sh, Makefile apple-* targets.

## Apple container stack (AppleContainerSetup.md)

- 6 containers: postgres (pgvector/pgvector:pg18 — multi-arch; the setup template's gzdaniel/postgres-for-rag:pg18-age-pgvector is amd64-only, no arm64 manifest), neo4j:5-community, milvus:v2.6.11 (CPU tag, NOT -gpu), milvus-etcd, milvus-minio, lightrag (ghcr.io/hkuds/lightrag:latest)
- Apple `container` 1.0.0 lacks: Compose, depends_on, healthcheck, restart policy, container-to-container service DNS (apple/container#856), working host bind mounts (apple/container#333, wontfix)
- Script compensations: explicit start ordering + /proc/net/tcp PORT_HEX health probes via `container exec`; IP wiring via `container inspect` (no DNS, no sudo); named volumes; `up` restarts stopped containers; seccomp:unconfined dropped (no shared-kernel sandbox)
- Only lightrag publishes a host port (127.0.0.1:9621); DBs reachable on vmnet IP with dev creds — trust boundary: single-user dev only
- Env handling: reads host `.env`, never modifies it; writes generated `.apple-container.env` (git-ignored, mode 600) overriding only storage vars; password precedence: shell var > .env value > dev default
- Memory budgets: LIGHTRAG_AC_MEM_HEAVY=6G (Milvus/Neo4j), LIGHTRAG_AC_MEM_LIGHT=2G (Postgres/LightRAG)
- Prereqs: macOS 26+ (container-to-container networking), Apple Silicon, container CLI installed + `container system start`, bash 4+ (system bash is 3.2; brew install bash)
- Make targets: apple-up / apple-down / apple-status / apple-logs SVC= / apple-restart / apple-pull; flags via SETUP_OPTS

## Single-container compose (docker-compose.yml / .podman.yml)

- One lightrag container; mounts ./data/{rag_storage,inputs,prompts}, injects ./.env, sets WORKING_DIR/INPUT_DIR, HOST=0.0.0.0, PORT=9621, restart on-failure
- docker-compose.yml: deploy.restart_policy + extra_hosts host.docker.internal:host-gateway
- docker-compose.podman.yml: top-level restart (podman rejects deploy block), no extra_hosts (podman auto-provides host.containers.internal — use that in .env bindings for host services)
- Best when file storage + containerized server wanted; one command, data on disk in ./data/

## Full GPU stack (docker-compose-full.yml)

- lightrag + vllm-embed + vllm-rerank + postgres + neo4j + milvus (+ etcd/minio); vLLM uses `runtime: nvidia` + CUDA dtype — NVIDIA-only, cannot run on Apple Silicon
- Generated by `make env-base` / `make storage` wizard → docker-compose.final.yml; gzdaniel/postgres-for-rag:pg18-age-pgvector (bundles Apache AGE + pgvector); SSL certs staged under ./data/certs/
- env.docker-compose-full is pre-wired for this GPU stack — Apple-container doc explicitly says do NOT start from it for local dev

## Decision rule of thumb

1. Read `.env` storage keys first (LIGHTRAG_*_STORAGE). File backends → path A or B only.
2. Docker-compatible runtime present (OrbStack/Docker Desktop) → never choose Apple container; it reimplements compose features by hand.
3. GPU/vLLM needs → only on NVIDIA hosts; never on Apple Silicon.
4. Production multi-user DB backend requirement → only then consider C/D.
