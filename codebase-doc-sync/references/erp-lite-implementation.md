# erp-lite: sync-wiki.py Implementation

Concrete example of the codebase-doc-sync pattern for a Laravel ERP project.

## Overview

Wiki at `~/wiki/erp-lite/` tracks the Laravel project at `~/xbot.my/erp-lite/`.
The `sync-wiki.py` script detects code changes and produces a structured report
for the LLM to analyze and update wiki content.

## Project Layout

```
~/wiki/erp-lite/
├── sync-wiki.py             # 3-layer detection script
├── .sync-state.json         # Stores last synced commit
├── build-wiki.py            # Static HTML viewer builder
├── index.html               # Generated single-file wiki viewer
├── SCHEMA.md                # Wiki domain schema
├── index.md                 # Page catalog
├── log.md                   # Action log
├── entities/                # Entity pages (customer, order, invoice, etc.)
├── concepts/                # Concept pages (state-machines, billing, etc.)
└── raw/                     # Immutable source files
```

## GitNexus Integration

Run with `--gitnexus` flag to enable symbol-level analysis:

```bash
python3 sync-wiki.py --gitnexus
```

This triggers:
1. `node .gitnexus/run.cjs analyze` — re-index the codebase (~35s)
2. `node .gitnexus/run.cjs detect-changes --scope compare --base-ref <commit>` — hunks-to-symbols mapping
3. Report includes: changed symbols count, affected execution flows count, risk level

GitNexus index built with 4,154 nodes, 5,174 edges for this project.

## HTML Viewer

The wiki has a self-contained static viewer (`index.html`) generated by
`build-wiki.py`. After updating wiki content:

```bash
python3 sync-wiki.py --rebuild
```

This runs `build-wiki.py` then saves sync state. The viewer is served via
Laravel Valet at `http://erp-lite.wiki.test/`.

## Complete Workflow

```bash
# Step 1: Detect changes
cd ~/wiki/erp-lite && python3 sync-wiki.py

# Step 2: (optional) Deep analysis with knowledge graph
python3 sync-wiki.py --gitnexus

# Step 3: LLM reads the report, uses MCP tools to analyze impact,
#         decides which wiki pages to update, and updates them

# Step 4: Rebuild after updates
python3 sync-wiki.py --rebuild
```

## MCP Tool Usage During Analysis

The LLM uses these tools (configured in Hermes session via project .mcp.json):

| MCP server | Tools used | Purpose |
|---|---|---|
| codebase-memory-mcp | search_graph, trace_path, get_code_snippet | Symbol lookup and call graph |
| codegraph | codegraph_explore | Source reading and call paths |
| laravel-boost | database_schema, application_info | Schema and version verification |
